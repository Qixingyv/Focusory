# Focusory 代码审查

按以下顺序审查改动：

1. 产品行为回归。
2. 前端和后端契约不一致。
3. 数据持久化和时间处理边界情况。
4. 功能文档的人工审核状态、日期、范围和基线是否有效，已审核测试场景是否与任务卡、测试代码和验收标准双向追踪。
5. 可自动化场景是否已落到合适的测试，不能自动化的场景是否写明可执行人工步骤、预期结果和不自动化原因。
6. 缺失测试或验证。
7. `文档/` 下的说明是否与实现偏离。

先列出发现的问题。尽可能包含文件和行号。如果没有发现问题，需要明确说明，并补充仍然存在的测试缺口。测试场景本身存在歧义、与权威规则冲突或反例证明设计无法成立时，按 `AGENTS.md` 的全程中断规则请人工确认，不要通过改测试追认实现。
