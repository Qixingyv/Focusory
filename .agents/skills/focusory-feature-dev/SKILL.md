# Focusory 功能开发

实现 Focusory 功能时，按以下流程执行：

1. 阅读 `文档/产品/功能` 中的对应功能文档，以及 `文档/产品`、`文档/架构` 和 `文档/AI开发` 下的相关文件；确认功能文档的人工审核状态为「已通过」，且审核范围覆盖当前任务。
2. 编辑前先检查已有前端和后端代码。
3. 复述目标行为和本任务覆盖的已审核测试场景编号，识别最小可实现范围。若人工审核记录缺失或失效、功能文档缺少测试场景、预期结果不唯一或场景与规则冲突，停止并请人工确认。
4. 根据已审核场景小步实现生产代码和相关测试。可根据改动性质安排两者的编写顺序，不强制在生产代码前先编写或运行失败测试。不得修改测试场景或测试来迎合与已审核设计不一致的实现。
5. 将可自动化场景落到适当的单元、集成、契约或 UI 测试，运行任务指定的测试、构建和检查命令。纯视觉、真实系统集成等不适合自动化的场景，保留可执行的人工测试步骤、预期结果和不自动化原因。
6. 当功能流程、接口或数据模型契约变化时，同步更新功能流程图和相关 IBM 4+1 文档。
7. 总结改动文件、场景编号与测试的对应关系、验证结果、遗留场景和后续需要记录的决策。
