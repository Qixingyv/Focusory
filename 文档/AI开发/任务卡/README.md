# 分支与任务卡索引

本目录保存开发任务及其所属职责分支的中文任务卡。分支名称只用于快速识别；任务卡是对应任务开发内容、Bug 范围、关联文档和验收标准的正式说明。

## 使用规则

1. 先确认所属功能和任务范围，再检查本索引并分配该功能下一个未使用的两位流水号；不归属具体产品功能的工程维护使用 `F00`。
2. 按 `F<功能编号>-<分支流水号>-<中文标题>.md` 创建任务卡，例如 `F01-02-修复计时归零后未停止.md`。
3. 任务卡经确认后，按根目录 [`AGENTS.md`](../../../AGENTS.md) 创建独立本地开发分支；分支名记录任务卡生成 AI，不记录实际开发执行者。
4. 开发、自动化验证、Codex 审查、正式提交、人工验收和合并顺序以 [`01-AI开发流程.md`](../01-AI开发流程.md) 为准。
5. 任务状态变化时同步更新本索引。已经登记、合并、删除或终止的流水号均不得重复使用。
6. 建立分支规则之前已经完成的历史任务卡保留原名，不补编分支编号。
7. 人工验收通过后仅将状态更新为 `已验收`；只有用户明确发出合并请求后，AI 才能执行合并并将状态更新为 `已合并`。

## 任务卡模板

```markdown
# 任务卡：<中文标题>

## 1. 分支信息

- 分支名称：`foc-<任务卡生成AI>-f<功能编号>-<流水号>-<分支类型>-<内容描述>`
- 中文标题：<一句话标题>
- 中文说明：<完整说明本分支开发的功能、修复的 Bug 或重构内容>
- 功能编号：F<两位数字>
- 分支流水号：<两位数字>
- 分支类型：功能开发 / Bug 修复 / 重构 / 工程维护
- 任务卡生成 AI：DeepSeek / ChatGPT / Codex / Claude / 其他明确名称
- 当前开发执行者：<AI、工具与模型；未分配时写“待分配”>
- 当前状态：待开发

### 相关文档

- 功能文档：[<Fxx-功能名称>](../../产品/功能/<Fxx-功能名称>.md) / 不涉及：<F00 工程维护等原因>
- 用例与业务规则：[<UC/BR 编号>](../../产品/02-用户故事.md) / 不涉及：<原因>
- 原型与 UI 规范：[<文档名称>](../../产品/<文档名称>.md) / 不涉及：<原因>
- 架构文档：[<文档名称>](../../架构/<文档名称>.md) / 不涉及：<原因>

## 2. 任务信息

- 优先级：P0 / P1 / P2
- 前置任务：<任务或无>
- 产品行为变更：有 / 无

## 3. 背景与问题

<说明当前状态、开发动机或 Bug 的表现、复现条件、预期行为和实际行为。>

## 4. 目标

<说明本任务必须完成的结果。>

## 5. 非目标

<说明明确不在本分支处理的内容。>

## 6. 前置阅读

<列出开始实现前必须阅读的规则、产品、架构、代码和测试。>

## 7. 影响模块与接口约束

<说明涉及模块、公开接口、数据、并发、兼容性和不得突破的边界。>

## 8. 实现步骤

<按依赖顺序列出可执行步骤。实现和测试必须覆盖已审核测试场景，但不强制在生产代码前先编写或运行失败测试。>

## 9. 测试场景与验收标准

<列出本任务覆盖的功能文档测试场景编号、场景与具体测试的建议映射，以及可观察、可判断的通过条件。不能自动化的场景写明编码前已确定的人工测试步骤、预期结果和不自动化原因。>

## 10. 验证命令

<列出自动化测试、构建或静态检查命令。>

## 11. 停止条件

实现或测试过程中发现需求歧义、规则缺失或冲突、产品偏离规则文件、验收标准矛盾、测试反例证明设计存在逻辑异常，或继续工作需要改变产品行为、数据语义、接口契约或任务范围时，立即停止受影响范围的工作并请人工确认。即使设计已经人工审核，此规则仍然有效。

## 12. 完成报告

- 修改文件：
- 测试场景映射：
- 验证结果：
- 未解决问题：
- 潜在风险：
- 人工验收结果：待验收
```

类型补充要求：

- `dev`：必须说明用户流程、业务规则、影响模块以及目标与非目标。
- `fix`：必须说明 Bug 表现、复现步骤、预期与实际行为、影响范围、根因或待调查点以及回归范围。
- `refactor`：必须说明重构原因、调整模块、不得改变的产品行为、风险和回归范围。
- `chore`：必须说明工程维护目标、影响范围、不得改变的产品行为、验证方式和回退边界，通常使用 `F00`。

不适用的文档项必须写明“不涉及”及原因，不得直接删除模板字段。

当前索引只管理本地分支，不记录远程分支或 Pull Request。未来启用远程协作前，先更新根目录规则与 AI 开发流程。
