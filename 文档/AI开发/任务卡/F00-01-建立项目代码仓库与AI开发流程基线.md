## 3. 背景与问题

项目根目录已经初始化 Git；`Focusory/` 曾包含独立的嵌套 Git 仓库，导致根仓库无法直接、完整地跟踪客户端源码。当前已经形成首个本地开发分支提交，人工验收期间又确认需要统一分支语义、开发执行者范围、人工审核留痕与测试场景追踪规则，因此继续在原任务中完成基线返工。

## 4. 目标

- 根目录成为唯一正式 Git 仓库，不保留任何嵌套 `.git` 目录。
- `main` 只建立仓库初始化基点，完整项目内容提交到本任务开发分支。
- 纳入源码、测试、构建配置、项目级 AI 配置、产品与架构文档以及正式资源。
- 排除构建产物、缓存、个人编辑器状态、运行数据和敏感配置。
- 运行当前项目可用的自动化验证，并在提交前记录结果和风险。
- 固化仅使用本地分支的 Git 流程，不配置或操作远程分支。
- 分支名记录任务卡生成 AI，开发执行者可为任意 AI 并在任务卡中单独记录。
- 为功能设计增加可持久追踪的人工审核记录，并保持设计、开发和审查技能一致。
- 明确通用规则类文档的聊天修改请求包含本地提交授权，产品相关改动仍须人工确认后提交。
- 固化功能文档的边界与接口写法：职责优先由泳道图表达，内部接口引用架构与代码，前后端接口统一引用 API 约定；同步设计技能和模板，避免重复维护。

- Git：只保留根目录 `.git`，开发分支按已确认格式命名。
- macOS 客户端：现有源码、测试、Xcode 工程和本地化资源只做纳管，不改变内容。
- Python 后端：仅纳管当前已存在的目录和配置，不补充尚未实现的后端结构。
- 文档与 AI 配置：纳入正式项目规则、技能、配置和文档；排除个人工作区状态。
- 产品行为：不得因流程基线返工修改现有功能、用例、业务规则或界面表现。
- 合并边界：本任务只提交本地开发分支，只有用户明确提出合并请求后才能合并 `main`。

## 8. 实现步骤

1. 查找并删除根目录以下的嵌套 `.git` 目录，确认源码文件保持不变。
2. 完善 `.gitignore`，覆盖构建产物、缓存、个人编辑器状态、本地环境和敏感配置。
3. 在 `main` 创建空的仓库初始化提交，再创建本任务开发分支。
4. 检查全部待提交文件，排除敏感信息、运行副产物和无关临时文件。
5. 运行当前可用的客户端构建和测试；记录无法运行的后端验证及原因。
6. Codex 审查待提交内容、验证结果和文档一致性。
7. 在人工验收返工中同步项目规则、AI 开发流程、任务卡模板、功能文档模板和相关技能，检查不存在互相冲突的旧表述。
8. 更新任务状态和完成报告，在开发分支创建正式提交，不合并 `main`。

- 根目录以下不存在嵌套 `.git` 目录。
