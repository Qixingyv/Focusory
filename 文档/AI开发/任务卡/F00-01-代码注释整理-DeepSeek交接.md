## 2. 背景和用户确认的写法

原注释：

```swift
/// 持有任务页面在主视图生命周期内共享的界面状态。
@State private var taskListModel: TaskListModel
```

用户认可的写法：

```swift
/// 保存任务列表状态，切换顶层页面时继续使用。
@State private var taskListModel: TaskListModel
```

注释应帮助读者理解变量“用来做什么”，并在不明显时补充“为什么在这里保存”。不要求每个变量都写两部分，不把短注释统一扩成模板句，不把注释变成 Swift 语法教程。

## 3. 目标与非目标

目标：

1. 检查根规则与注释原则是否一致、直接且可执行。
2. 检查整个项目现有 Swift 源码、单元测试、集成测试和 UI 测试中的注释，保留清楚准确的说明，修订含糊、冗长、误导或只重复代码的说明。
3. 状态变量按需要说明影响什么界面、空值含义、保存位置和共享范围；回调说明何时触发以及交给谁处理。
4. 保留事务、账户隔离、时间归属、失败结果、幂等和终态等重要约束，不为通俗而删掉契约。
5. 核对已做修改，完成可运行的验证，并交回 Codex 审查与人工检查。

非目标：不改生产逻辑、声明、命名、接口、测试断言、测试场景、用户文案、资源、数据库结构或产品文档；不修复顺便发现的实现问题，不新增依赖或注释检查工具，不整理生成文件、缓存和第三方代码。Python 后端当前没有业务源码，不虚构后端注释工作。

## 5. 前置阅读和代码入口

| 位置 | 阅读重点 |
