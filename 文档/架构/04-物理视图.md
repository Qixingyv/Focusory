# Focusory 物理视图

## 目的、受众与交付标准

- 目的：描述原型生产实现的部署节点、网络、数据存储、访问控制、运行环境和备份恢复。
- 受众：后端、客户端发布、运维和安全人员。
- 交付物：产品运行时的部署拓扑、节点责任、安全边界和恢复要求。
- 交付标准：可指导本地开发和生产部署，不将数据库或密钥暴露给公网。

## 部署拓扑

```text
macOS 设备
 ├─ Focusory.app
 ├─ SwiftData 本地数据库
 └─ Keychain 登录凭据
        │ HTTPS
        ▼
公网入口 / 反向代理
        │
        ▼
Python Focusory API
 ├─ Python 3.12.10 + FastAPI/Uvicorn
 ├─ Apple 身份验证
 ├─ 微信扫码登录
 └─ SQLAlchemy/PyMySQL 私有网络连接
```

## 客户端节点

- 运行环境：项目支持的 macOS 最低版本与对应 Xcode/Swift 工具链。
- 业务数据：存入应用沙盒中的 SwiftData 存储。
- 凭据：只存入 Keychain，不存入 UserDefaults、SwiftData 业务表或日志。
- 网络断开时保持本地任务、计时和统计可用。

## 服务端节点

- API 使用 Python 3.12.10 标准构建，由 Uvicorn 运行 FastAPI 应用；依赖以 `uv.lock` 锁定。
- API 只通过 TLS 入口对外提供 HTTPS。
- MySQL 只对 API 私有网络开放，不直接暴露公网端口。
- 生产 MySQL 优先使用托管实例，使用 InnoDB、`utf8mb4`、静态/备份加密和可验证的恢复机制。
- API 实例尽量无状态；登录态和同步真实数据不依赖单个进程内存。
- 第三方密钥通过生产环境的机密管理提供，不提交到仓库或镜像。

## 访问控制

- 除登录和健康检查外，API 验证 Focusory 登录态。
- 每次数据查询从经过验证的用户 ID 限制范围，不接受客户端自由指定他人 `user_id`。
- 登录、扫码状态和同步接口需要限流和审计日志。
- 日志不记录第三方令牌、完整会话凭据或同步负载中的敏感字段。

## 本地开发

- macOS 客户端可仅使用本地存储运行原型核心闭环。
- Python API 使用 `uv` 管理本地 Python 3.12.10 环境；MySQL 作为独立集成环境启动。
- 本地 MySQL 继续只绑定 `127.0.0.1`，业务表由迁移工具建立。
- 开发辅助 MCP Server 与产品 API 使用独立进程和包边界。

## 备份与恢复

- MySQL 执行定期自动备份，并定期验证可恢复性；具体 RPO/RTO 在上线前根据部署平台确定。
- 迁移前需有可恢复备份与回滚方案。
- 客户端本地数据损坏时，优先保留可读副本和诊断信息，不在未告知用户时静默重置。
- 已同步账户可从云端重建本地副本；未同步变更需单独保护，不能被拉取结果直接覆盖。
