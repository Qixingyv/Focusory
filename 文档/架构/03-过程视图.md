# Focusory 过程视图

## 目的、受众与交付标准

- 目的：说明运行时进程、并发、通信、性能、数据一致性、容错和恢复策略。
- 受众：客户端、后端、测试和运维人员。
- 交付物：运行时单元、串并行规则、超时重试与恢复策略。
- 交付标准：正在专注的计时不被网络与同步阻塞，完成会话不重复也不丢失。

## 运行时单元

- macOS 主进程：SwiftUI 界面、领域状态、本地存储和同步调度。
- UI 主执行器：只处理视图状态发布和必要的用户交互。
- 计时任务：以可取消任务触发界面刷新，真实时间来自时钟和目标结束时刻。
- 同步执行器：串行处理当前账户的本地变更，防止乱序覆盖。
- Python API 进程：并发处理多用户 HTTP 请求。
- MySQL：使用唯一约束、事务和行版本保证幂等与一致性。

## 计时与本地优先策略

- 专注开始时保存目标结束时刻；界面刷新按当前时刻重新计算剩余时间，不把刷新次数当作真实时间。
- 暂停时保存剩余时长，继续时产生新的目标结束时刻；实际专注时长排除暂停时间。
- 日期和今日统计使用本机 Calendar 与 IANA 时区，不从 UTC 日期字符串直接截取。
- 时间和日历能力必须可注入，以覆盖暂停、恢复、跨日、系统休眠和时钟校正测试。
- 任务、会话、每日进度和同步变更先原子写入本地，界面随后从本地数据更新。
- 本地写入由 `LocalTransaction` 统一提交：仓储在事务内只暂存写入，提交失败时业务对象与待同步变更一起回滚；SwiftData 上下文关闭自动保存，避免出现「任务已保存但同步变更未保存」的中间结果。
- 任务命令与查询按 F01 的用例顺序在 UI 主执行器上串行执行；P0 不引入后台写入队列，因此同一用户操作不会并发进入同一命令。
- 计时器和本地成功路径不等待网络；网络失败不得回滚已成功的本地会话。
- 应用重启后从活跃计时快照恢复；到期完成处理必须保证只执行一次。

## 串并行规则

可并行：

- UI 计时展示刷新与后台同步。
- 通知请求与已完成会话的后续同步。
- 不同用户的后端请求。

必须串行或原子处理：

- 同一计时器的开始、暂停、继续、完成和取消。
- 完成会话时的会话、任务进度、每日进度与同步队列写入。
- 同一任务的目标追加与生命周期变更，以及与其同事务的同步队列写入。
- 同一 `operation_id` 的重复提交：本地在写入前查询同步队列，已存在时返回重放结果而不再次修改目标。
- 同一账户的退出清理与同步写入。
- 同一 `operation_id` 的服务端处理。
- 同一账户的身份绑定与解绑；解绑必须在事务中锁定账户身份集合，防止并发操作删除最后一个身份。

## 通信与超时

- 客户端与后端使用 HTTPS + JSON。
- 交互请求设置明确超时；同步请求超时后回到待同步/失败状态。
- 只有幂等写操作才自动重试，使用指数退避与随机抖动。
- 计时器不向后端发送每秒心跳。

## 性能目标

- 开始、暂停和继续操作在本地 100 ms 内更新可见状态。
- 任务页的列表查询、计数与写入在个人数据量下保持即时；即使单条记录无法还原，也返回可重试错误而不是静默丢弃。
- 倒计时可见误差不超过 1 秒，窗口失焦或系统短暂休眠后按当前时刻校正。
- 任务与今日列表在个人数据量下保持即时交互；列表查询在需要时分页。
- 同步不得占用主线程或导致计时显示卡顿。

## 容错与恢复

- 应用重启：从 ActiveTimerSnapshot 和当前时刻恢复；已过结束时刻时只执行一次完成。
- 本地存储打不开：显示可重试的启动错误，不用空内存存储静默顶替，避免让用户以为任务丢失。
- 本地记录损坏：查询返回可重试的失败状态，不把损坏记录当作不存在。
- 断网：本地保存继续，同步状态改为离线或待同步。
- 后端 5xx/超时：保留队列项并延迟重试。
- 验证失效：暂停云同步并请求重新登录，不删除本地未同步数据。
- 数据冲突：保留服务端版本与本地操作记录，不静默丢弃会话；具体合并策略需在同步实现前决策。
