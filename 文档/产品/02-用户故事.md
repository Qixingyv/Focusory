# Focusory 用例视图

## 1. 视图说明

### 1.1 目的

本文件是 Focusory 用例规格与编号化业务规则的唯一真值源。

产品范围与 MVP 边界来自 [`01-产品需求.md`](./01-产品需求.md)；功能文档引用本文件中的 UC 与 BR 编号，不重新定义规则。

用例视图从用户角度回答「Focusory 应该为用户做什么」，具体用于：

- 捕获功能需求，明确系统范围、用户目标和可见结果。
- 让产品、设计、开发和测试对主流程、失败分支和业务规则建立共识。
- 驱动逻辑视图、开发视图、过程视图和物理视图，并用于检查架构是否覆盖了全部关键用例。

### 1.2 受众

- 用户和产品人员：确认系统能做什么、是否符合预期。
- 架构师和技术负责人：确认架构覆盖范围、用例依赖和交付风险。
- 开发人员：理解需要实现的正常流程、异常分支和校验点。
- 测试人员：将每个流程、分支、业务规则和非功能要求转换为测试用例。
- 项目管理者：根据优先级、依赖和验收范围估算工作量。

### 1.3 交付物与交付标准

| 交付物 | 内容 | 交付标准 |
| --- | --- | --- |
| 用例图 | 角色、系统边界、用例及关系 | 非技术人员可以看懂用户能做什么，技术人员可以识别系统范围 |
| 用例规格 | 前置条件、触发器、成功流程、失败流程、后置条件和验收标准 | 主流程无歧义，关键异常已识别，每个 P0 用例可直接转换为测试 |
| 业务规则 | 可独立引用的编号化规则 | 同一规则在产品、逻辑、数据和测试中语义一致 |
| 非功能需求 | 可靠性、一致性、性能、可用性和安全 | 具有可验证的结果或测试方式 |
| 关系与优先级矩阵 | 用例依赖、规则扩展、优先级和迭代边界 | 可用于安排实现顺序和检查其他视图的覆盖性 |

### 1.4 原型解读基线

- 本次视图以 2026-08-29 的「番茄钟原型初版」React + TypeScript 演示代码为交互基线，覆盖登录、任务、专注、休息、统计、同步状态和退出登录。
- 原型中的页面、按钮、文案、可见状态和跨页面流程用于确认产品行为；内存数组、模拟延时登录、逐秒递减和随机标识等仅用于演示，不作为生产实现约束。
- 若演示代码的临时实现与可靠性原则冲突，视图保留可验证的产品语义，例如以可靠时钟计算剩余时间、以本机日期归属会话、以本地原子提交保存完成结果。
- 2026-08-31 确认的多身份绑定要求扩展了原型账户能力：一个 Focusory 账户可同时绑定 Apple 和微信，本视图中的 UC-14 与 BR-ACC-04 至 BR-ACC-07 是新的产品基线。
- 压缩包内的说明文档只作为原型背景材料；本视图中的 UC、BR 和验收标准才是后续实现与测试使用的需求基线。

## 2. 系统范围与角色

### 2.1 当前范围

当前产品基线是 macOS 个人番茄钟，围绕「任务 → 一轮专注 → 会话记录 → 今日统计」形成本地闭环，再通过账户与同步扩展为跨设备数据闭环。

当前不包含项目、标签、子任务、多人协作、趋势图、AI 复盘、游戏化、菜单栏常驻入口和持续任务过期处理。

### 2.2 角色

| 角色 | 说明 | 主要目标 |
| --- | --- | --- |
| 未登录用户 | 尚未获得 Focusory 会话的人 | 完成登录并进入自己的工作空间 |
| 专注用户 | 已进入本人工作空间的主要使用者 | 管理任务、专注计时、休息并查看真实投入 |
| 第三方身份服务 | Apple 或微信身份验证服务 | 向 Focusory 返回身份验证结果 |
| Focusory 云端 | 保存账户的云端副本并处理同步 | 确认幂等变更，返回服务端变更 |

## 4. 统一业务规则

### 4.1 账户与数据所有权

- **BR-ACC-01**：登录方式只能是 Apple 或微信，同一次登录处理中不得重复提交。
- **BR-ACC-02**：任务、会话、每日进度和同步变更都属于当前账户。
- **BR-ACC-03**：退出登录只清理当前账户的本机数据，不删除云端数据。
- **BR-ACC-04**：一个 Focusory 账户可同时绑定一个 Apple 身份和一个微信身份；任一第三方身份在全局最多属于一个 Focusory 账户。
- **BR-ACC-05**：通过任一已绑定身份登录必须进入同一账户及其工作空间；不根据邮箱、昵称或其他可变属性自动合并账户。
- **BR-ACC-06**：绑定第二种身份前必须存在有效 Focusory 登录态并重新完成该第三方验证；若身份已属于另一账户，拒绝绑定且不自动合并数据。
- **BR-ACC-07**：用户可解绑已绑定身份，但不得解绑账户的最后一个登录身份；绑定和解绑都必须原子提交并防止并发操作破坏该约束。

### 4.2 任务通用规则

- **BR-TASK-01**：任务只有「待办」和「持续」两种模式，创建后不可转换。
- **BR-TASK-02**：名称必填；专注时长为 5 至 120 分钟且以 5 分钟为步长，休息时长为 1 至 60 分钟；默认分别为 25 分钟和 5 分钟。
- **BR-TASK-03**：整体状态只有进行中、已完成和已放弃；已完成和已放弃不得再开始会话。
- **BR-TASK-04**：运行或暂停计时时，当前任务被锁定，不得切换、删除、放弃或最终完成；允许编辑不得改变任务关联或重算本轮倒计时，其中计时时长配置只影响未来轮次，每日基础目标只影响未来日期。
- **BR-TASK-05**：无会话的进行中任务可删除；已有会话的进行中任务只能放弃，且必须保留历史会话和统计。
- **BR-TASK-06**：手动完成、删除和放弃都是危险操作，必须在用户明确确认后执行。
- **BR-TASK-07**：从任务列表点击「开始专注」时，系统选择该任务、切换到专注页并立即启动计时；仅选择任务本身不得隐式启动计时。
- **BR-TASK-08**：每次目标追加在修改数据前生成唯一操作标识；同一操作标识在本地和云端都最多生效一次，提交处理中不得重复触发同一命令。

### 4.3 待办与持续模式规则

- **BR-TODO-01**：待办任务的目标番茄数必须是正整数，只能增加，不得减少。
- **BR-TODO-02**：只有会话保存成功后才增加待办进度；达到目标时产生「按计划完成」反馈，但任务整体状态仍为进行中，用户可以直接继续专注。
- **BR-TODO-03**：按计划完成后可追加正整数目标，追加后按新目标重新计算反馈；仅当新目标大于已完成数时恢复未达标进度。追加不是继续专注的前置条件，手动最终完成后不可追加或恢复。
- **BR-TODO-04**：待办追加提供「追加 1 个」和自定义数量两种入口；一次追加执行 `新目标 = 当前目标 + 追加数量`，只修改目标和待同步变更，不创建会话、不增加已完成数，也不改变统计。
- **BR-ONGOING-01**：持续任务不设整体番茄数目标；计划周期和每日目标可独立开关，共有四种合法组合。
- **BR-ONGOING-02**：创建持续任务时，计划开始日不得早于本机今日，截止日不得早于开始日。编辑尚无会话的任务时可修改开始日，新开始日不得早于本机今日；已有会话后开始日锁定。截止日被修改时不得早于本机今日或开始日；未修改的历史开始日或截止日即使已经过去，也不阻止修改名称、计时时长等其他字段。未到开始日不得专注；截止日当前只用于展示，不触发过期或自动完成。
- **BR-ONGOING-03**：开启每日目标时，当日有效目标等于当日目标快照加当日追加数量；每日进度以任务和本机日期唯一。
- **BR-ONGOING-04**：今日达标只显示「今日已达标」，不会完成整个持续任务，也不阻止继续专注；用户可选追加正整数目标，追加只影响当日。
- **BR-ONGOING-05**：每日目标的配置修改从下一个本机日期起生效，不重写当日或历史快照；产生会话后不可再切换两个配置开关。
- **BR-ONGOING-06**：番茄数累计或今日达标都不会自动完成持续任务，只有用户手动确认才能最终完成。
- **BR-ONGOING-07**：持续任务今日达标后可「追加 1 个」或追加自定义正整数；一次追加执行 `当日追加数 = 原当日追加数 + 追加数量`，只改变当前任务当前本机日期的有效目标，不修改每日基础目标、其他日期、会话或统计。
- **BR-ONGOING-08**：追加当日目标提交前必须再次校验本机日期；若已跨日，则不得把追加写入上一日，系统刷新为新日期的每日进度并要求用户重新操作。

### 4.4 计时、会话与统计规则

- **BR-TIMER-01**：同一账户同一时刻最多有一个活跃计时器；开始专注前必须选择可用任务。
- **BR-TIMER-02**：运行中的剩余时间由目标结束时刻与可控时钟决定，不由界面刷新次数累减。
- **BR-TIMER-03**：暂停时保留剩余时间；继续后以保留值生成新的目标结束时刻。
- **BR-TIMER-04**：专注自然完成或中途「记录为完成」在本地保存成功后，以及休息自然结束时，都触发系统通知与提示音；界面反馈保持低干扰，不要求窗口处于前台。
- **BR-SESSION-01**：一轮专注最多生成一条会话；只有自然完成或用户选择「记录为完成」才生成。
- **BR-SESSION-02**：「放弃本次」和休息不生成会话，不更新任务进度或统计。
- **BR-SESSION-03**：中途记录完成保存排除暂停后的实际专注时长；历史会话保留完成时的任务名快照。
- **BR-SESSION-04**：会话、任务进度、每日进度和待同步变更必须在一次本地原子提交中保存。
- **BR-STATS-01**：统计只从已保存的专注会话推导，不单独维护可被直接修改的统计结果。
- **BR-STATS-02**：今日番茄数等于今日会话数，今日专注总时长等于今日会话实际专注时长之和。
- **BR-STATS-03**：跨零点会话归入结束时的本机日期，明细按结束时间倒序。

### 4.5 本地优先与同步规则

- **BR-SYNC-01**：本地保存先于网络上传，后端不可用不得中断计时或丢失已提交的本地记录。
- **BR-SYNC-02**：同步状态为已同步、离线、等待同步、正在同步或同步失败。
- **BR-SYNC-03**：待同步变更具有唯一操作标识，只有云端明确确认后才视为完成。
- **BR-SYNC-04**：网络恢复后自动处理待同步变更，同步失败不使用打断专注的强制弹窗。

## 5. 用例规格

所有会修改本地数据的用例共享一条失败处理原则：若本地原子提交失败，则整次修改回滚，不向用户展示部分成功，并给出可重试且不破坏原数据的错误结果。各用例下方只再列出其特有失败分支。

### UC-01 登录

- **主要角色**：未登录用户。
- **协作者**：第三方身份服务。
- **前置条件**：用户处于登录页，当前无有效登录会话。
- **触发器**：用户选择 Apple 登录或微信扫码登录。
- **主成功流程**：
  1. Focusory 标记登录处理中并防止重复提交。
  2. 第三方身份服务完成验证。
  3. Focusory 按「provider + provider user ID」查找身份绑定；已存在时进入所属账户，首次登录时原子创建账户和首条身份绑定。
  4. Focusory 建立当前账户会话并进入主窗口。
  5. F05 将当前账户的数据准备请求交给 F06，不等待同步完成才确认登录成功；具体拉取与恢复归 UC-10。
  6. 系统从本地显示当前账户数据；云端数据成功应用后刷新。已有本地任务可立即使用，无本地任务且初始化未完成时显示同步进度，不把本地零条视为云端无任务。
- **失败或备选流程**：
  - 用户取消或身份验证失败：停留在登录页，显示可理解的结果并允许重试。
  - 登录请求已在处理：忽略重复触发，不创建第二次请求。
  - 登录成功后首次数据拉取或本地应用失败：保留登录会话和已提交的本地数据，显示可重试同步失败；不报任务不存在、不显示已确认空态，恢复后重试。
- **成功后置条件**：存在唯一当前账户会话。
- **引用规则**：BR-ACC-01、BR-ACC-02、BR-ACC-04、BR-ACC-05。
- **验收标准**：成功、取消、认证失败和重复点击四条路径均有确定结果；Apple 和微信均绑定后，任一方式登录都返回同一账户 ID 和数据；首次在本机登录或退出清理后重新登录能恢复云端数据，首次同步中、同步失败与确认无任务可区分（交接见 F05-TS-01 至 03；同步见 F06-TS-01 至 03；任务页展示见 F01-TS-34 至 36）。

### UC-02 创建任务

- **主要角色**：专注用户。
- **前置条件**：用户已进入工作空间。
- **触发器**：用户点击「新建任务」。
- **主成功流程**：
  1. 用户选择待办或持续模式。
  2. 用户填写名称、专注时长、休息时长和对应模式配置。
  3. Focusory 验证通用规则和模式特有规则。
  4. Focusory 保存进行中任务，将其显示在任务列表并设为当前选中任务。
- **失败或备选流程**：
  - 名称为空、数量或时长越界：不保存，在对应字段附近提示。
  - 截止日早于开始日：不保存，提示修正日期范围。
  - 用户取消：不创建任务。
- **成功后置条件**：新任务为进行中，模式已固定。
- **引用规则**：BR-TASK-01、BR-TASK-02、BR-TODO-01、BR-ONGOING-01、BR-ONGOING-02。
- **验收标准**：待办可合法创建；持续任务的两个开关可组成四种合法配置；非法配置不产生数据。

### UC-03 完成一轮专注

- **主要角色**：专注用户。
- **前置条件**：存在可用的进行中任务，当前无其他活跃计时。
- **触发器**：用户在专注页或任务行选择「开始专注」。
- **主成功流程**：
  1. Focusory 检查任务整体状态、日期范围和当日目标状态。
  2. 计时器关联当前任务，记录开始时刻与目标结束时刻，锁定任务。
  3. 倒计时自然归零后，Focusory 仅创建一条完成会话。
  4. Focusory 在一次本地原子提交中保存会话、任务进度、每日进度和同步变更。
  5. 系统触发通知与提示音并显示完成反馈，今日统计可立即查看新会话。
- **失败或备选流程**：
  - 无选中任务、任务已完成或已放弃：不启动计时，提示选择可用任务。
  - 持续任务未到开始日：不启动计时，显示开始日。
  - 待办已按计划完成或持续任务今日已达标：仍可开始下一轮，保留达标反馈；用户可稍后选择追加目标。
  - 本地原子提交失败：不展示已保存结果，不部分增加任务进度。
  - 网络不可用：本地成功仍算完成，转入待同步状态。
- **成功后置条件**：存在且仅存在一条新会话，相关进度和统计可从其正确推导。
- **引用规则**：BR-TASK-03、BR-TASK-04、BR-TASK-07、BR-TIMER-01 至 BR-TIMER-04、BR-SESSION-01 至 BR-SESSION-04。
- **验收标准**：窗口失去焦点、界面刷新延迟或网络中断都不改变真实剩余时间，重复完成事件不重复产生会话。

### UC-04 暂停、继续或中途结束

- **主要角色**：专注用户。
- **前置条件**：一轮专注正在运行。
- **触发器**：用户点击暂停。
- **主成功流程**：
  1. Focusory 保留实际剩余时间并进入已暂停。
  2. 用户点击继续，Focusory 以已保留的剩余时间恢复计时。
  3. 流程返回 UC-03 的运行中阶段。
- **失败或备选流程**：
  - 用户选择「记录为完成」：保存实际专注时长，然后执行 UC-03 的原子提交、通知和完成反馈。
  - 用户选择「放弃本次」：不生成会话，不更新进度，计时器返回空闲。
  - 用户选择「继续专注」：关闭中途结束弹窗，保持已暂停，由用户再次显式继续。
- **成功后置条件**：计时器处于专注中、专注完成或空闲之一，不存在模糊中间状态。
- **引用规则**：BR-TASK-04、BR-TIMER-03、BR-TIMER-04、BR-SESSION-01 至 BR-SESSION-03。
- **验收标准**：暂停时时间不继续减少；三个中途结束选项分别导向上述唯一结果。

### UC-05 手动休息

- **主要角色**：专注用户。
- **前置条件**：一轮专注已成功保存。
- **触发器**：用户选择开始休息。
- **主成功流程**：系统按当前任务的休息时长启动休息；自然归零后触发通知与提示音、返回空闲，并显示约 4 秒的轻量提示。
- **失败或备选流程**：
  - 用户不开始休息：直接返回专注页空闲状态。
  - 用户手动结束休息：立即返回空闲。
  - 用户跳过休息并开始下一轮：结束休息，重新执行 UC-03 的任务可用性检查并立即开始专注。
- **成功后置条件**：休息不产生会话或统计记录。
- **引用规则**：BR-TIMER-04、BR-SESSION-02。
- **验收标准**：专注完成后不自动休息；自然结束、手动结束和跳过都不改变专注统计。

### UC-06 使用待办目标

- **主要角色**：专注用户。
- **前置条件**：存在进行中的待办任务。
- **触发器**：会话保存后进度达到目标，或用户操作已达标任务。
- **主成功流程**：
  1. 会话保存成功后，系统重新计算已完成番茄数。
  2. 达到目标时，任务显示「任务已按计划完成」，仍留在进行中页并可继续专注。
  3. 用户若选择提高目标，执行 UC-12；追加不是继续专注的前置条件。
- **失败或备选流程**：
  - 用户手动完成任务：执行 UC-08，此后不提供追加。
- **成功后置条件**：任务保持进行中，可保留按计划完成反馈、继续累计投入，或按新目标恢复进度反馈。
- **引用规则**：BR-TODO-01 至 BR-TODO-03。
- **验收标准**：达标前一次、正好达标、达标后直接继续、追加后再达标和手动完成后五种边界均有确定结果；界面不使用「超额完成」作为新状态。

### UC-07 使用持续任务

- **主要角色**：专注用户。
- **前置条件**：存在进行中的持续任务。
- **触发器**：用户查看、专注、编辑未来每日目标或追加当日目标。
- **主成功流程**：
  1. Focusory 按配置展示日期范围、今日进度、历史番茄数和累计时长。
  2. 会话保存成功后，Focusory 将其计入结束时所在的本机日期。
  3. 今日完成数达到有效目标时，显示「今日已达标」，整体任务仍为进行中。
  4. 用户无需追加即可继续专注；若选择提高今日目标，执行 UC-13。
- **失败或备选流程**：
  - 未开启每日目标：不创建目标快照，只展示累计投入。
  - 进入新的本机日期：使用新日期的进度与目标快照，不覆盖历史日期。
- **成功后置条件**：历史快照保持不变，今日进度与今日追加一致。
- **引用规则**：BR-ONGOING-01 至 BR-ONGOING-06、BR-STATS-03。
- **验收标准**：四种配置、未到开始日、今日达标后直接继续、当日追加、未来目标编辑和跨零点均有自动化验证；超过目标时仍显示达标而不是新增「超额」状态。

### UC-08 管理任务生命周期

- **主要角色**：专注用户。
- **前置条件**：存在任务。
- **触发器**：用户选择编辑、完成、删除或放弃。
- **主成功流程**：
  1. 编辑时，Focusory 只允许修改当前规则允许的字段，验证后保存；运行或暂停中允许的编辑不得改变当前任务关联或本轮计时配置。
  2. 手动完成时，用户确认后任务进入已完成，此后只读。
- **失败或备选流程**：
  - 无会话的进行中任务选择删除：确认后移除任务。
  - 有会话的进行中任务选择删除：不允许删除，改为提供「放弃」；确认后任务进入已放弃。
  - 计时正在运行或暂停：拒绝切换、最终完成、删除和放弃当前任务；对未来轮次或未来日期生效的安全编辑仍可保存。
  - 持续任务已有会话后修改开始日：拒绝保存并保留输入；尚无会话时可把开始日改为本机今日或未来日期。
  - 持续任务修改截止日到本机今日之前或开始日之前：拒绝保存并在日期范围附近提示；未修改的历史日期不阻止保存其他字段。
  - 用户取消确认：不改变任务。
- **成功后置条件**：任务和历史数据符合保留规则，不存在可被恢复的已完成或已放弃任务。
- **引用规则**：BR-TASK-03 至 BR-TASK-06、BR-TODO-03、BR-ONGOING-05、BR-ONGOING-06。
- **验收标准**：有无会话、有无活跃计时、确认与取消的组合都不会误删历史数据；持续任务开始日的历史锁定、截止日的修改边界与未修改历史日期均有确定结果。

### UC-09 查看今日统计

- **主要角色**：专注用户。
- **前置条件**：用户已进入工作空间；今日可以没有会话。
- **触发器**：用户打开统计页。
- **主成功流程**：
  1. Focusory 按当前本机日期查询已保存的会话。
  2. 系统展示会话数、实际专注总时长和按结束时间倒序的明细；每条明细包含任务名快照、开始与结束时间和实际专注时长。
- **失败或备选流程**：
  - 今日无会话：展示零番茄、零专注时长和空明细，不视为错误。
  - 存在放弃本次、休息或已放弃任务：前两者不进入统计，已放弃任务的历史会话仍进入统计。
- **成功后置条件**：不修改任何业务数据。
- **引用规则**：BR-SESSION-02、BR-SESSION-03、BR-STATS-01 至 BR-STATS-03。
- **验收标准**：自然完成、中途记录、放弃本次、休息和跨零点的统计口径均正确。

### UC-10 离线使用与同步

- **主要角色**：专注用户。
- **协作者**：Focusory 云端。
- **前置条件**：P1 已建立当前账户会话；本机可以尚无业务数据副本。
- **触发器**：P1 登录成功、本地数据发生变更、网络从不可用恢复为可用，或用户重试初始化。
- **主成功流程**：
  1. 登录成功后，同步模块按当前账户拉取云端数据；无本机副本时完成初始化，上传队列为空也必须拉取。
  2. 本地业务变更先在本地与待同步变更一起提交；网络可用时按唯一操作标识发送到云端。
  3. 云端明确确认后，Focusory 将对应变更标记为已同步，并继续获取云端新变更。
  4. Focusory 按账户应用拉取结果，成功后更新同步位置并通知页面重查本地；初次完整拉取应用成功后标记初始化完成，云端确认无任务也视为成功。
- **失败或备选流程**：
  - 网络不可用：保留本地数据与待同步变更，不中断计时、任务操作或统计查看。
  - 上传失败或超时：保留变更并显示弱化的失败状态，后续重试。
  - 同一操作重复上传：云端按操作标识幂等确认，不重复创建会话或进度。
  - 首次拉取或本地应用失败：不标记初始化完成，不推进同步位置；无本地任务时显示可重试同步失败，不把未拉取数据当作任务不存在或已确认空态。
  - 拉取期间发生本地修改：已提交结果保留，不被云端副本直接覆盖；冲突合并策略仍待 F06 决策。
  - 拉取期间退出或切换账户：旧账户响应不得写入新账户副本或恢复已退出账户的页面数据。
- **成功后置条件**：已确认变更不再等待上传，云端数据成为当前账户本机可查询副本，本地已提交业务数据在整个过程中可用。
- **引用规则**：BR-SESSION-04、BR-SYNC-01 至 BR-SYNC-04。
- **验收标准**：离线创建任务和会话后重启应用，数据仍存在；恢复网络后可自动且幂等同步；无本机副本且上传队列为空时仍能拉取云端任务；初始化失败可重试、空结果可确认，拉取不覆盖未确认本地变更且不跨账户应用（F06-TS-01 至 F06-TS-07；最终冲突预期仍由 F06-TS-08 待决策）。

### UC-11 退出登录

- **主要角色**：专注用户。
- **前置条件**：存在当前登录账户。
- **触发器**：用户选择退出登录。
- **主成功流程**：
  1. Focusory 提示将清理当前账户的本机数据，云端数据保留。
  2. 用户明确确认。
  3. Focusory 清理当前账户的本机任务、会话、每日进度、统计缓存和待同步变更。
  4. Focusory 销毁当前会话并返回登录页。
- **失败或备选流程**：用户取消时，保持登录和本机数据不变。
- **成功后置条件**：本机无当前账户会话及其本地数据，云端数据不受影响。
- **引用规则**：BR-ACC-03。
- **验收标准**：确认后本机当前账户数据被完整清理；取消时不发生部分清理。

### UC-14 管理登录身份绑定

- **主要角色**：专注用户。
- **协作者**：Apple 或微信身份服务。
- **前置条件**：存在有效 Focusory 登录会话，当前账户至少有一个已绑定身份。
- **触发器**：用户在账户设置中选择绑定未绑定的 Apple/微信身份，或解绑其中一个已绑定身份。
- **绑定成功流程**：
  1. Focusory 确认当前账户尚未绑定目标 provider，并标记绑定处理中。
  2. 用户在目标第三方完成新一次身份验证。
  3. Focusory 验证第三方凭据，并确认该「provider + provider user ID」未属于其他账户。
  4. Focusory 在单一服务端事务中创建身份绑定，返回完整的已绑定 provider 集合。
  5. 账户设置显示 Apple 和微信均已绑定，现有任务、会话和统计不变。
- **解绑成功流程**：
  1. Focusory 要求用户确认解绑的 provider。
  2. 服务端在事务内锁定当前账户及其身份集合，确认解绑后仍至少保留一个身份。
  3. 服务端删除目标绑定并返回剩余 provider 集合；业务数据不变。
- **失败或备选流程**：
  - 用户取消或第三方验证失败：不修改绑定。
  - 当前账户已绑定目标 provider 且是同一身份：按幂等成功返回当前绑定集合。
  - 第三方身份已绑定另一 Focusory 账户：返回身份冲突，不合并账户或数据。
  - 尝试为同一 provider 改绑另一身份：拒绝原地替换；必须先保证另一 provider 可登录，再解绑和重新绑定。
  - 尝试解绑最后一个身份：拒绝操作，账户保持可登录。
  - 并发绑定/解绑与数据库唯一约束冲突：回滚事务，刷新最新绑定状态。
- **成功后置条件**：一个 Focusory 账户始终保留一至两条合法身份绑定，业务数据所有者 ID 不变。
- **引用规则**：BR-ACC-04 至 BR-ACC-07。
- **验收标准**：覆盖 Apple 绑定微信、微信绑定 Apple、任一方式重新登录、重复绑定、跨账户冲突、解绑其中一个、拒绝解绑最后一个及并发操作。

### UC-12 待办达标后追加目标

- **主要角色**：专注用户。
- **前置条件**：待办任务整体状态为进行中，且已完成番茄数大于或等于当前目标；任务未被手动最终完成或放弃。
- **触发器**：用户在「任务已按计划完成」反馈中选择「追加 1 个番茄钟」或提交自定义追加数量。
- **主成功流程**：
  1. Focusory 读取待办任务当前目标和已完成番茄数。
  2. 系统验证追加数量为正整数，并计算 `新目标 = 当前目标 + 追加数量`。
  3. 系统重新计算目标反馈：若新目标大于已完成数，任务目标子状态恢复为进行中；否则继续保持按计划完成。
  4. Focusory 在一次本地原子提交中保存新目标和待同步变更。
  5. 系统显示新的「已完成数/目标数」，用户可通过 UC-03 开始下一轮专注。
- **失败或备选流程**：
  - 追加数量为空、不是整数或小于 1：不修改目标，在输入处提示。
  - 提交前任务已被最终完成或放弃：拒绝追加并刷新任务状态。
  - 本地提交失败：目标和同步变更全部回滚，保留原目标与原反馈。
  - 网络不可用：本地追加仍成功，变更进入等待同步。
- **成功后置条件**：待办总目标按一次命令只增加一次；已完成数、既有会话和统计不变。
- **引用规则**：BR-TASK-03、BR-TASK-08、BR-TODO-01 至 BR-TODO-04、BR-SYNC-01 至 BR-SYNC-03。
- **验收标准**：`2/2 + 1 → 2/3` 并恢复进行中；`3/2 + 1 → 3/3` 仍保持按计划完成；`3/2 + 2 → 3/4` 恢复进行中；重复上传同一追加操作不得重复增加目标。

### UC-13 持续任务今日达标后追加目标

- **主要角色**：专注用户。
- **前置条件**：持续任务整体状态为进行中、已开启每日目标，当前本机日期的完成数大于或等于当日有效目标。
- **触发器**：用户在「今日已达标」反馈中选择「追加 1 个番茄钟」或提交自定义追加数量。
- **主成功流程**：
  1. Focusory 获取当前本机日期，并读取该任务该日期唯一的每日进度。
  2. 系统验证追加数量为正整数，并计算 `新当日追加数 = 原当日追加数 + 追加数量`。
  3. 系统计算 `新当日有效目标 = 当日目标快照 + 新当日追加数`。
  4. 若新有效目标大于今日完成数，今日目标子状态恢复为进行中；否则继续保持今日已达标。
  5. Focusory 在一次本地原子提交中保存当日进度和待同步变更。
  6. 系统显示新的「今日完成数/今日有效目标」，用户可通过 UC-03 开始下一轮专注。
- **失败或备选流程**：
  - 追加数量为空、不是整数或小于 1：不修改当日目标，在输入处提示。
  - 提交时本机日期已变化：不写入上一日，刷新新日期进度并提示用户重新操作。
  - 每日目标已关闭，或任务已最终完成、放弃：拒绝追加并刷新任务状态。
  - 本地提交失败：当日追加数和同步变更全部回滚。
  - 网络不可用：本地追加仍成功，变更进入等待同步。
- **成功后置条件**：只有当前任务当前本机日期的追加数发生变化；每日基础目标、其他日期、会话、累计完成数和统计不变。
- **引用规则**：BR-TASK-03、BR-TASK-08、BR-ONGOING-03、BR-ONGOING-04、BR-ONGOING-07、BR-ONGOING-08、BR-SYNC-01 至 BR-SYNC-03。
- **验收标准**：基础目标为 2 时，`今日 2/2 + 1 → 今日 2/3` 且明日基础目标仍为 2；`今日 3/2 + 1 → 今日 3/3` 仍保持达标；跨零点提交不得修改上一日；重复上传同一追加操作不得重复增加当日目标。

### 优先级定义

- **P0**：形成任务、专注、会话和今日统计的本地可用闭环，是 MVP 发布必需。
- **P1**：形成账户与云同步闭环，不应阻塞 P0 的本地可用性。

## 8. 对其他视图的驱动要求

- 逻辑视图必须提供能承载 UC-01 至 UC-14 的领域对象、关系、交互和状态机，其中账户身份绑定不得与业务数据所有者混合。
- 开发视图必须为每个用例指定模块边界、对外契约和单向依赖。
- 过程视图必须解释计时、本地原子提交和异步同步如何并行且保持一致。
- 物理视图必须说明 macOS 本地节点在离线时如何独立承载 P0 用例，以及 P1 的云端节点如何接入。
